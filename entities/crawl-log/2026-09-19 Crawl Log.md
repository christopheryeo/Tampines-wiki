#### Lessons learned

- **Wire-syndication inflates raw vault-bar acceptance far above genuine story count.** A single AP-
  style story reported by ~20 outlets can each independently pass topic-fit and the vault bar,
  producing a raw accepted count that looks like a bar failure but is actually one story counted 20
  times. NewsAPI.ai's `isDuplicate` flag catches exact syndicate mirrors (34/62 today) but not
  independently-written coverage of the same event by different outlets (a further 12/28 today) —
  that second layer requires a same-event content check before cascade, not just a provider flag.
- **Multi-outlet consolidation must happen before enrichment, and enrichment must not undo it.**
  `enrich_radar_inputs.py`'s outlet-identity pass replaces the note's `outlets` list with its own
  single-outlet assessment (derived from the body text's byline), discarding any additional outlets
  recorded at Step 8 normalization. Today this was caught by an explicit post-enrichment diff-check
  against the pre-enrichment consolidation record and repaired before cascade; an unattended run
  without that check would silently lose verified multi-outlet coverage and undercount
  `coverageCount`.
- **`ingest_cascade`'s Coverage routing can diverge from the note's own recorded `topic` field.**
  Cascade links a compiled article into topics matched by its enrichment-derived tags, which is a
  different signal from the `topic` frontmatter value carried through via `--preserve-topic`. For 3
  of 16 articles today the two disagreed, requiring a `scripts/patch_coverage.py` repair pass after
  cascade. The Step 10.5 "assert every cascaded article is linked" check is therefore not a formality
  — it caught a real, silent gap on 19% of today's batch.
- **A Dropbox "Resource deadlock avoided" (EDEADLK) lock can strand a catalog rebuild indefinitely.**
  `generate_catalog.py topic` failed on every retry for over 100 seconds after a batch of direct
  frontmatter edits (`patch_coverage.py`) to entities in that domain. Deleting the stale target file
  and letting the script recreate it fresh resolved this immediately — a plain retry loop on the
  existing inode did not.

#### Recommendations to improve the topic crawl plan

- **Evidence:** raw vault-bar acceptance was 62 for a 96-topic run against the guideline that "more
  than ~15 accepted should trigger a re-check that top-tier-regional isn't admitting routine
  coverage." The re-check found the bar itself was applied correctly per-article; the inflation was
  wire syndication (34 provider-duplicate + 12 same-event-different-outlet), not bar leakage.
- **Recommended change:** add an explicit Step 7 sub-step — after the Singapore-strategic vault bar,
  group the accepted set by same-real-world-event (using each candidate's own title/body evidence,
  never model background knowledge) before normalization, compiling one canonical note per event with
  the fullest verbatim body and every corroborating outlet recorded in `outlets`. Pair this with a
  documented enrichment contract: `enrich_radar_inputs.py`'s outlet pass must either preserve a
  pre-existing multi-outlet `outlets` list (an `--preserve-outlets` flag, symmetrical to
  `--preserve-topic`) or normalization must apply outlet consolidation strictly after enrichment, not
  before.
- **Implementation:** not applied to the tracked plan or scripts this run — flagged here as a
  genuine, evidence-backed candidate for the Part B methodology PR rather than implemented ad hoc
  inside the daily run, since it touches both the plan's Step 7/8 contract and `enrich_radar_inputs.py`'s
  outlet-resolution behavior and deserves review.
- **Expected accuracy benefit:** removes a ~4x overcount risk (62 raw → 16 genuine stories today) from
  ever reaching cascade undetected, and prevents silent loss of verified multi-outlet corroboration
  when enrichment runs after normalization.
- **Expected OpenAI API-call reduction:** none directly (consolidation is a post-hoc grouping step on
  an already-small accepted set); the larger-volume calls (triage, relevance, vault bar) are unchanged.
