#### Lessons learned

- **A 3am SGT crawl start is structurally early-window, not an anomaly to fix.** For the second run
  in a row (also true on 2026-09-20), a run starting ~03:00–03:10 SGT covers only ~3–3.5 hours of the
  local calendar day, so the great majority of the day's eventual news has not yet been published.
  Today's 75-candidate, 4-accepted yield is a legitimate reflection of window size, not a discovery
  failure — the date gate correctly excluded 2026-09-20-dated stories that both SET A passes kept
  surfacing (most of the raw pass-1/pass-2 hits were still dated 2026-09-20 SGT).
- **Pooled/generic-term SET A retries do not substitute for grounded SET B on zero-result Singapore
  topics.** Pass 2's narrow single-token retries (`MINDEF`, `Singapore Armed Forces`, `Singapore
  Army`, `cyber defence`, etc.) independently corroborated the pass-1 zeros, which is useful
  confirmatory evidence, but a generic high-volume retry (`defense`: 6,308 raw rows; `research`:
  4,877) is not triageable by hand and was correctly left unexamined rather than skimmed
  superficially — matching the plan's own high-volume-recall caution.
- **`ingest_cascade`'s tag-based Coverage routing continues to add topics beyond the note's own
  `topic` field**, as already documented on 2026-09-19/20 — today's South China Sea article was also
  cross-listed under `military-exercises` and `republic-of-singapore-navy` by the cascade's own tag
  matching. This is pre-existing, acknowledged behaviour (Step 10.5's known limitation), not a defect
  introduced this run; verifying the *intended* primary topic's backlink (done) remains the
  sufficient check.
