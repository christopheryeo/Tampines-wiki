#### Lessons learned

- **A genuinely busier UN General Assembly week produces a genuinely higher accepted count, and that
  is a correct read of the bar, not scope creep.** Today's 8 accepted (vs. 4 on 2026-09-21, 2–3 on
  prior days) spans a week with an active Iran conflict, an active Russia-Ukraine drone-strike
  exchange, a Trump-Xi summit two days out, and UNGA diplomacy in New York — a day genuinely denser
  with major state-level developments a Singapore defence desk would brief on. This stayed well under
  the ~15-per-day re-check threshold and each item was independently justified against the vault bar,
  not counted toward a target.
- **Multi-outlet syndication of the same statement is common and must be collapsed to one accepted
  article, not four.** The Iran IRGC "geography of war" warning was independently reported by four
  outlets (Al-Monitor, Tehran Times, WTX News, Redstate) with near-identical content; only the most
  complete, least partisan source (Al-Monitor) was cascaded, with the others recorded as the same
  underlying event rather than separate acceptances.
- **A truncated/paywalled snippet does not automatically mean `held` — check for a complete
  alternate-outlet SET A article covering the same event first.** Yesterday's precedent (the Telegraph
  Iran item) was correctly held because no complete alternate existed; today's Telegraph
  Trump-Zelensky item had one (jowhar.com), so it was accepted via the alternate instead of held.
- **`--check-complete` and a raw YAML-parse check are not the same gate, and both are needed before
  cascade.** Today's frontmatter corruption produced files that were plausibly well-formed by eye but
  failed `yaml.safe_load` outright. A direct parse check on every normalized/enriched file, immediately
  after `--apply` and before the cascade dry-run, is now essential — see Recommendations.

#### Recommendations to improve the topic crawl plan

- **Evidence:** `scripts/enrich_radar_inputs.py`'s `parse_frontmatter`/`replace_fields` hardcoded a
  two-space block-list-item indent (`"  - "`), which does not match the zero-indent block-list style
  that `yaml.safe_dump(default_flow_style=False)` — a common, standards-compliant YAML emitter
  default — produces. On `--apply`, this silently corrupted `outlets`/`countries` for all 8 of today's
  candidates (empty-list misread on parse, then orphaned dash lines left behind on write), which would
  have broken cascade if not caught by an explicit YAML-parse check before Step 10.
- **Recommended change:** implemented this run — `LIST_ITEM_RE = re.compile(r"^\s*-\s?(.*)$")` now
  matches a block-sequence item at any indentation in both `parse_frontmatter` and `replace_fields`.
  Regression tests added (`test_frontmatter_parser_reads_zero_indent_block_lists`,
  `test_apply_overwrites_zero_indent_block_list_without_orphaning_lines`). PR #41 opened:
  https://github.com/christopheryeo/Tampines-wiki/pull/41
- **Implementation:** `scripts/enrich_radar_inputs.py` (2 call sites), `tests/test_enrich_radar_inputs.py`
  (2 new tests). Verified against `origin/main` in an isolated worktree: 15 passed (13 existing + 2
  new), 2 pre-existing failures unrelated to this change (`args.offset` AttributeError in
  manifest-routing tests, present on `origin/main` before this branch).
- **Expected accuracy benefit / API-call reduction:** prevents a class of silent frontmatter corruption
  that would otherwise surface as an opaque cascade failure or, worse, a partially-corrupted note that
  passes a shallow check; no direct API-call change, but avoids re-running enrichment (and its model
  calls) on notes that have to be regenerated after a corruption is discovered post-hoc.
