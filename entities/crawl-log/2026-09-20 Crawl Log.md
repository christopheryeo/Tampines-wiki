#### Lessons learned

- **The Singapore-strategic vault bar's `sg-nexus` tier needs a substantive-nexus check, not a
  keyword check.** A Singapore-dateline ICA/CNB drug-smuggling bust at Tuas Checkpoint was tiered
  `sg-nexus` by the automated second pass purely on "Singapore" + "checkpoint" + agency-acronym
  language, despite having no SAF/MINDEF/defence-security substance. The written rule already says a
  Singapore dateline or outlet is "NOT enough — the substance must involve Singapore [defence]", but
  the model under-applied it for ordinary law-enforcement reporting. This run caught it only because
  every raw-accepted candidate was read individually during the required >15 syndication re-check;
  on a day where the raw accepted count stayed under the ~15 threshold, this class of false positive
  would reach cascade undetected.
- **One dominant global story can still trigger the over-admission guideline without any bar
  leakage.** 33 of 42 raw-accepted candidates today were one Trump-Denmark-Greenland security
  announcement, confirming the 2026-09-19 finding that wire syndication (exact copies) and
  independent multi-outlet coverage of the same announcement (here, 14 further outlets with no
  `isDuplicate` flag between them) both inflate the raw count independently of bar correctness. The
  same-event consolidation step is doing exactly the job it was flagged for on 2026-09-19.
- **The enrichment outlet-identity pass still overwrites a pre-consolidated multi-outlet list.** The
  2026-09-19 recommendation to add a `--preserve-outlets` flag (symmetrical to `--preserve-topic`) to
  `enrich_radar_inputs.py` has not yet been implemented; today's run hit the identical failure mode
  on 1 of 6 notes and required the same manual pre/post diff-and-restore. This is now a repeat
  observation across two consecutive daily runs.

#### Recommendations to improve the topic crawl plan

- **Evidence:** a Singapore-dateline, non-defence law-enforcement story (Tuas Checkpoint cannabis
  bust) was tiered `sg-nexus` by the automated vault-bar pass today and required a manual override
  during the required syndication re-check — the same class of risk the >15 over-admission guideline
  exists to catch, but this particular failure mode (false-positive nexus, not routine-coverage
  leakage) is not what that re-check is optimized to find.
- **Recommended change:** tighten `bin/vaultbar.py`'s `sg-nexus` rule text to require the article's
  own body to name a SAF/MINDEF/defence-security actor or activity, not merely a Singapore
  government agency handling a non-defence matter (customs, immigration, ordinary crime); add one
  worked counter-example (a Singapore customs/drug bust) alongside the existing rule so the model
  has a concrete negative anchor, matching how the `routine` tier already gets one.
- **Implementation:** not applied to the tracked plan or `bin/vaultbar.py` this run — `bin/` is a
  per-run scratch toolkit copied into each day's run directory, not a tracked script, so a durable
  fix belongs in a reviewed change to `scripts/topic_crawl_plan.md`'s vault-bar rule text (and any
  future promotion of the `bin/` toolkit into `scripts/`) rather than an ad hoc edit inside today's
  run folder.
- **Expected accuracy benefit:** removes a recurring false-positive class (non-defence Singapore
  law-enforcement stories tiered `sg-nexus`) that currently depends on a human/agent noticing it
  during the manual syndication re-check rather than being caught mechanically.
- **Expected OpenAI API-call reduction:** none directly — this is a precision fix to an existing
  pass, not a volume reduction. The standing 2026-09-19 recommendation (pre-normalization same-event
  consolidation as a formal Step 7 sub-step, plus an `enrich_radar_inputs.py --preserve-outlets`
  flag) remains the higher-value outstanding change and was evidenced again today; it is still not
  implemented and is re-flagged here rather than duplicated as a new recommendation.
