#### Lessons learned

- **A per-topic Crawl-Prompt-derived query is not always usable, and the plan's own recommended
  Singapore-anchor-pool strategy is the more reliable default for this vault.** Several broad-category
  topics have no distinctive non-generic subject vocabulary to query on alone; forcing a per-topic query
  for them produces unusable noise (tens of thousands of results/day) rather than a narrow, triageable
  set. The two-tier anchor-query approach used this run is worth making the documented default rather
  than a fallback.
- **The 2026-09-26/27/28 gap cost two genuine Singapore-nexus items.** Both the RSAF runway relocation
  and the Singapore Defense Tech Hackathon stories were published 2026-09-28 SGT and fell inside that
  gap; a today-only run correctly cannot recover them under this run's scope, but the gap itself (three
  consecutive days with no completed daily crawl) is worth Christopher's attention as an operational
  continuity issue, independent of today's OpenAI blocker.
- **An account-level API credential/billing failure blocks the entire pipeline downstream of
  enrichment, and must be surfaced as an explicit, human-actionable blocker rather than worked around.**
  No candidate's tone/sentiment/event-type/tags were inferred outside the calibrated two-pass model
  process to route around the failure; all 4 candidates are held, not lost.

#### Recommendations to improve the topic crawl plan

- **Evidence:** `scripts/topic_crawl_fetch.py --keyword` only accepted a single string, joined by the
  caller into `"a OR b"` when a topic's Crawl Prompt had multiple terms — a literal phrase to the
  provider that matches nothing (confirmed: the 2026-09-28 session's pre-fix run returned
  `totalResults: 0` for all 96 topics and a `Trump` control keyword, in a window where real coverage
  demonstrably existed).
- **Recommended change:** implemented (carried over from the 2026-09-28 session, independently
  re-verified this run) — `--keyword` is now `action="append"` (repeatable), and a new
  `keyword_payload()` helper submits a single term as a phrase or multiple terms as a provider `keyword`
  array with `keywordOper: "or"`. Regression tests: `test_single_keyword_is_submitted_as_a_phrase`,
  `test_multiple_keywords_are_submitted_as_an_or_array`, `test_empty_keywords_is_rejected` (plus the
  pre-existing provider-window tests, 5/5 total pass).
- **Implementation:** `scripts/topic_crawl_fetch.py`, `tests/test_topic_crawl_fetch.py`. Verified
  against `origin/main` in an isolated git worktree branch before opening a PR (see final report for the
  PR link).
- **Expected accuracy benefit / API-call reduction:** directly fixes false-negative SET A results for
  every canonical topic whose Crawl Prompt has more than one core-subject term (the majority of the 96)
  — this was previously silently returning zero real coverage every day for those topics regardless of
  actual news volume. No change to per-call cost; this is a correctness fix, not a call-count change.
