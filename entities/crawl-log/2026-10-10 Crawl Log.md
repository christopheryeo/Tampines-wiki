#### Lessons learned

- **A per-run Singapore-anchor substitution must exclude the topic's original high-volume file, not
  merely un-exclude the topic from the `HIGH_VOLUME` set.** This run's first collection pass
  recovered the 3 Singapore-institutional topics from high-volume status by discarding them from the
  exclusion set, which silently re-admitted their noisy full keyword-array pass2 file (the actual
  source of the high-volume problem) alongside the clean narrow sg-anchor file, instead of the narrow
  file substituting for it. The defect was caught by inspecting the shortlist before triage (RSAF and
  RSN false-positive matches reappeared) and fixed by keeping the topic in the exclusion set for the
  generic scan while separately always including its sg-anchor file. This is a defect in this run's
  own ad hoc, untracked driver script (copied forward from 2026-10-09's `collect_candidates.py` under
  `runs/**/artifacts/`, which is gitignored), not in `scripts/topic_crawl_plan.md` or a tracked
  production script, so no PR is warranted — but any future run reusing this driver script pattern
  should carry the fix forward (keep the original high-volume file excluded; add the sg-anchor file
  as a separate, always-included source) rather than re-introducing the bug.
- **A carried-forward `pass2-keywords.json` can silently omit topics whose pass-1 zero-result set
  differs night to night.** This run copied forward the prior day's hand-curated pass-2 keyword
  variants file as a shortcut and found it lacked entries for 4 of today's 62 pass-1 zero-result
  topics (`americas-security`, `defence-budget-spending`, `south-asia-security`,
  `unmanned-systems-drones` — topics that had non-zero pass-1 results on 2026-10-09 so were absent
  from that day's pass-2 file). Caught by diffing the zero-result set against the carried-forward
  file's keys before running pass 2; fixed by deriving missing variants directly from each topic's
  `keywords` field in `topics/canonical-topics.yaml`. Future runs should derive the full pass-2
  keyword set fresh from `topics/canonical-topics.yaml` for every pass-1 zero-result topic each run,
  rather than copying forward a prior day's file, to avoid this silent-gap class of error.
- **A zero-accept day is a legitimate, expected outcome and was reached honestly.** Several
  candidates were close calls (the UAE-coast vessel strike, the Russia-Ukraine missile-facility
  strike) and the strict daily bar's "when in doubt, drop it" instruction resolved each of them to a
  reject rather than padding the accepted count — consistent with the plan's explicit statement that
  most days, most topics will legitimately close with zero.
